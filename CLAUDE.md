# CLAUDE.md

Правила для агента при работе с этим репозиторием.

## Структура репозитория

- `kit-setup/` — Kotlin multi-module Gradle проект, ядро AI-Kit. Релизится на GitHub как исполняемые файлы для Windows / Linux / macOS.
- `docs/` — сайт документации на React.
- `README.md` — верхнеуровневое описание проекта (на русском). Это **источник истины** для пользователя.

## Правила релиза

Релиз — это атомарная процедура. Шаги выполняются строго в порядке ниже и в одном коммите-баампе:

### 1. Определить тип версии (SemVer `MAJOR.MINOR.PATCH`)

| Что изменилось | Тип бампа |
|---|---|
| Манифест бандла сломал обратную совместимость (изменился `schemaVersion`, удалены/переименованы поля) | **MAJOR** |
| В манифест добавлены опциональные поля или новые значения enum'ов без поломки существующих бандлов | **MINOR** |
| Изменились **только** шаблоны (контент `*.md`, новая версия шаблона внутри бандла) — манифест и код не трогались | **PATCH** |

Если в релиз попадают изменения нескольких категорий — берётся **самая высокая**: код + шаблоны = по правилам кода; MAJOR + PATCH = MAJOR.

### 2. Актуализировать документацию

Перед бампом проверить и при необходимости обновить:

- `README.md` в корне — описание, манифест, примеры. Должен отражать текущую версию.
- `docs/` — страницы документации React-сайта. Если изменился публичный API CLI или формат манифеста — синхронизировать.

Если документация не соответствует изменениям — релиз не делается, сначала правится документация.

### 3. Бамп-коммит и тег

Один коммит, содержащий:
- обновлённую версию в `kit-setup/gradle.properties` (или `libs.versions.toml`, если версия хранится там),
- обновлённую версию в `docs/package.json`,
- актуализированный `README.md` и `docs/`.

Сообщение коммита:

```
chore(release): vX.Y.Z

<кратко: что вошло в релиз>
```

Тег:

```
git tag vX.Y.Z
git push origin main --tags
```

Имя тега — строго `vX.Y.Z`, без префиксов и суффиксов. GitHub Actions по этому тегу собирает исполняемые файлы под Windows / Linux / macOS и публикует release.

### 4. После пуша

Убедиться, что:
- workflow сборки релиза прошёл успешно,
- в GitHub Releases появились артефакты для всех трёх платформ,
- ссылки в `docs/` на «последнюю версию» по-прежнему валидны.

## Чего делать нельзя

- ❌ Создавать тег без коммита-бампа (тег должен указывать на коммит с поднятой версией).
- ❌ Пересоздавать существующий тег (force-push тегов запрещён — артефакты в GitHub Releases уже опубликованы).
- ❌ Бампить только версию без проверки `README.md` и `docs/`.
- ❌ Объединять релизный коммит с фичами — бамп-коммит делает **только** бамп и актуализацию документации.
- ❌ Помечать изменение шаблонов как MINOR/MAJOR — для шаблонов всегда PATCH, если манифест не менялся.

## Когда сомнения

Если непонятно, какой тип бампа применить — спросить у пользователя. Лучше уточнить, чем выпустить мажор как патч (или наоборот).
