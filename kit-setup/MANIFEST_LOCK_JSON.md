# `.aikit/manifest.lock.json`

Реестр файлов, сгенерированных последним успешным запуском `kit-setup generate` (или `kit-setup update`). Лежит рядом с пользовательским манифестом — в `.aikit/manifest.lock.json` относительно корня проекта.

Lock-файл — служебный артефакт CLI. Пользователю **не нужно** его редактировать, но и удалять без причины тоже не стоит: без него `kit-setup remove` не знает, какие файлы принадлежат AI-Kit, а какие написал пользователь. Если lock потерян — выполните `kit-setup generate <MANIFEST>` ещё раз; пока бандл и inputs не менялись, lock восстановится с теми же путями и хешами.

## Зачем он нужен

1. **Drift-detection.** Перед перезаписью файла `generate` сверяет его текущее содержимое с записанным хешем. Если хеш изменился — пользователь редактировал файл вручную, и CLI без `--force` его НЕ перезаписывает.
2. **Orphan-удаление.** Если в новом рендере бандла файла нет, но он есть в старом lock — CLI безопасно его удаляет (предварительно проверив, что хеш на диске совпадает с записанным).
3. **Безопасный `remove`.** Команда `kit-setup remove` удаляет только пути из lock; всё остальное в `.claude/`, `.opencode/`, `.qwen/` остаётся нетронутым.

## Схема

```json
{
  "lockVersion": "1",
  "aikitVersion": "0.1.0",
  "generatedAt": "",
  "manifestRef": ".aikit/manifest.autonomous.json",
  "applications": [
    {
      "id": "root",
      "path": ".",
      "targets": {
        "claude": {
          "bundle": "simple-kit@0.0.1",
          "source": "internal",
          "files": [
            { "path": ".claude/CLAUDE.md",                "sha256": "65aa…03a19" },
            { "path": ".claude/commands/review.md",       "sha256": "2459…3261b" },
            { "path": ".claude/hooks/session-start.sh",   "sha256": "7cd1…0c25e0" }
          ]
        }
      }
    }
  ]
}
```

### Поля верхнего уровня

| Поле           | Тип    | Значение                                                                                       |
|----------------|--------|------------------------------------------------------------------------------------------------|
| `lockVersion`  | string | Версия формата lock-файла. Сейчас всегда `"1"`. Поднимается отдельно от `aikitVersion`.        |
| `aikitVersion` | string | Версия CLI, которая записала lock. Диагностика; на логику CLI не влияет.                       |
| `generatedAt`  | string | ISO-8601 UTC временной метки. Может быть пустой строкой, если CLI не может определить время.   |
| `manifestRef`  | string? | Путь манифеста (относительно корня проекта), из которого сделан generate. Используется для определения смены манифеста при следующем `generate`. `null` в lock'ах, созданных до v0.1.0. |
| `applications` | array  | По одной записи на каждое application из проектного манифеста, в том же порядке.               |

### `applications[]`

Зеркалит `applications[]` из `.aikit/manifest.json`:

| Поле     | Тип    | Значение                                                                                  |
|----------|--------|-------------------------------------------------------------------------------------------|
| `id`     | string | Тот же идентификатор, что в манифесте (например, `"root"`).                               |
| `path`   | string | Тот же относительный путь, что в манифесте (`"."`, `"./backend"`).                        |
| `targets`| object | Ключ — имя агента (`"claude"`, `"opencode"`, …), значение — описание см. ниже.            |

### `targets.<agent>`

| Поле     | Тип    | Значение                                                                                  |
|----------|--------|-------------------------------------------------------------------------------------------|
| `bundle` | string | `name@version`, как в манифесте.                                                          |
| `source` | string | `"internal"` или путь к директории / zip — как в манифесте.                               |
| `files`  | array  | Список объектов `{ path, sha256 }` — все файлы, которые этот target сгенерировал.         |

### `files[]`

| Поле     | Тип    | Значение                                                                                  |
|----------|--------|-------------------------------------------------------------------------------------------|
| `path`   | string | POSIX-style путь относительно корня проекта (директории, содержащей `.aikit/`).           |
| `sha256` | string | Lowercase hex SHA-256 хеш итогового содержимого файла (после AKEL/подстановок).           |

## Алгоритм работы CLI

### `generate` / `update`

1. Прочитать lock (если есть) — это `oldLock`. Если отсутствует — `oldLock = null`.
2. Отрисовать все шаблоны в память. Для каждого получаем `(relPath, bytes)`.
3. Посчитать `newHash = sha256(bytes)` для каждого файла.
4. Для каждого `(relPath, bytes, newHash)` определить действие:
   - На диске файла нет → **create**.
   - В `oldLock` файл есть, его записанный хеш равен текущему хешу файла на диске:
     - Если `newHash == oldHash` → **unchanged** (не пишем).
     - Иначе → **update**.
   - В `oldLock` файл есть, но текущий хеш файла отличается от записанного:
     - Без `--force` → **skip-drift** (предупреждение, файл не трогаем).
     - С `--force` → **update**.
   - Файла нет в `oldLock`, но есть на диске → **create** (перезаписываем; считается «случайным» файлом, не охраняемым lock).
5. Найти orphan'ы: пути, которые были в `oldLock`, но не появились в новом рендере.
   - Если файл всё ещё на диске и его хеш совпадает с записанным → **delete-orphan**.
   - Если хеш не совпадает (пользователь правил) → **keep-drifted-orphan** (предупреждение, оставляем).
6. Записать новый lock полностью (а не патчить).

### `remove`

1. Прочитать lock. Если отсутствует — ошибка `LockNotFound`.
2. Для каждого `(relPath, recordedHash)`:
   - Файла нет на диске → **missing** (просто учли в отчёте).
   - Хеш на диске совпадает с записанным → **delete**.
   - Хеш отличается → **skip-drift** (с `--force` — всё равно **delete**).
3. После удаления подчистить пустые родительские каталоги (только в пределах корня проекта).
4. Если не задан `--keep-manifest` — удалить `.aikit/manifest.json` и `.aikit/manifest.lock.json`, и саму папку `.aikit/`, если она опустела (`.aikit/bundles/` остаётся).

## Хеширование

Используется **SHA-256** от итоговых байт файла (после AKEL и подстановки `${bundle.input.*}`). Реализация хеша pure-Kotlin, идентичная на linuxX64 / macosArm64 / mingwX64 — drift-detection детерминирован между сборками CLI.

Lock хранит хеш в поле `sha256` (lowercase hex, без `0x`-префиксов и пробелов). Поле названо в честь алгоритма; если в будущем потребуется сменить алгоритм, появится либо новое поле, либо `lockVersion` будет инкрементирован.

## Совместимость

- `lockVersion = "1"` — текущая версия формата.
- CLI игнорирует неизвестные поля верхнего уровня и в `targets` — это даёт пространство для аддитивных расширений без бампа `lockVersion`.
- Любое **breaking** изменение (переименование поля, смена алгоритма хеша, изменение нормализации путей) обязано увеличить `lockVersion` и поломать чтение старого формата — это, в свою очередь, MAJOR-релиз CLI.

## Что НЕ хранится в lock

- Содержимое файлов — только хеш.
- Inputs пользовательского манифеста — они есть в `.aikit/manifest.json`, дублировать незачем.
- Списки скилов / подагентов сверх того, что выражается в путях файлов — путь сам по себе говорит, что было включено.
- Любая информация о пользователе или его окружении.

## Что делать, если lock «битый»

- Если JSON не парсится → удалите lock и перезапустите `generate`. CLI воспримет это как первый запуск (никаких drift-проверок, всё перезапишется).
- Если хеши «не сходятся» после ручной правки CLI — проверьте, не редактировали ли вы файл; используйте `--force` для перезаписи или верните файл к содержимому, отражающему хеш.
- Удалять lock из-под `kit-setup remove` нельзя — команда откажется работать и попросит сначала запустить `generate`.
