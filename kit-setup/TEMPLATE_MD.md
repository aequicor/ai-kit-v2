# Шаблоны .md

Markdown-файлы внутри бандла (агенты, slash-команды, скилы, `CLAUDE.md`-фрагменты и т. п.) могут содержать **подстановки** и **условные блоки**, которые раскрываются при установке бандла. После обработки на диск ложится обычный .md, без следов шаблонных конструкций.

Принцип симметричен `CONFIG_JSON.md`: ровно две управляющие конструкции, один и тот же язык выражений (AKEL).

## Управляющие конструкции

### 1. Подстановка значения: `${bundle.input.<id>}`

Тот же синтаксис, что и в `config.json`. Работает в любом месте файла — в тексте, во frontmatter, в кодовых блоках за пределами code fences (см. ниже).

```md
# Review для ${bundle.input.projectName}

Модель: **${bundle.input.model}**, temperature `${bundle.input.temperature}`.
```

Сериализация по типу input'а:

| Тип input | Подстановка |
|---|---|
| `boolean` | `true` / `false` |
| `int`, `double` | число как есть |
| `string`, `select` | строка как есть |
| `multiselect` | элементы через `, ` (например, `review, security-review`) |

### 2. Условный блок: `<!-- when: <expr> --> … <!-- end -->`

HTML-комментарий с префиксом `when:` открывает блок, парный `<!-- end -->` закрывает. Содержимое блока попадает в итоговый файл только если выражение → `true`.

```md
Базовая инструкция, всегда применима.

<!-- when: ${bundle.input.strict} -->
В strict-режиме запрещены `rm -rf` и force push.
<!-- end -->

<!-- when: ${bundle.input.profile} == 'full' -->
Полный профиль: статический анализ + тесты + security-review.
<!-- end -->
```

Внутри `when:` живёт AKEL — тот же мини-язык выражений, что в `config.json` (литералы, `==`/`!=`, `<`/`>`, `&&`/`||`/`!`, `in`, ссылки `${bundle.input.<id>}`). Полная спецификация — `CONFIG_JSON.md`, раздел «Язык выражений (AKEL)».

## Правила обработки

1. **Сначала вырезаются `false`-блоки `when`.** Парсер ищет парный `<!-- end -->` для каждого открывающего `<!-- when: … -->`, поддерживает вложенность.
2. **Затем выполняется подстановка `${bundle.input.<id>}`** в оставшемся тексте.
3. **Маркер `when`/`end` на отдельной строке** удаляется вместе с переводом строки — пустых строк-артефактов в итоговом файле не остаётся.
4. **Code fences (` ``` ` и ` ~~~ `) игнорируются** парсером: внутри них `<!-- when: … -->` остаётся текстом, `${bundle.input.<id>}` не подставляется. Это нужно, чтобы примеры кода в скилах и инструкциях не превращались в случайные подстановки.

## Что намеренно не входит

| Не входит | Альтернатива / почему |
|---|---|
| Итерация (`for x in …`) | Покрывается интерполяцией `multiselect` (`${bundle.input.skills}` → `review, init`) и несколькими `when`-блоками. Если станет частым кейсом — добавим отдельно. |
| `else` / `elif` | Пиши два соседних `when` с противоположными условиями. |
| AKEL-выражения вне `when:` | Выражения только в `when:`. В тексте — только подстановки. |
| Шаблонизация имён файлов | `config.json` управляет тем, какие файлы попадают в установку, и через какие имена. Шаблон отвечает только за содержимое. |
| Пользовательские функции, фильтры (`upper`, `length`, …) | Поверхность поддержки большая, ценность сомнительная. Отложено. |

## Ошибки

| Ситуация | Поведение |
|---|---|
| Открытый `<!-- when: … -->` без `<!-- end -->` | прерывание установки с указанием строки |
| `<!-- end -->` без открывающего `when` | прерывание |
| Синтаксическая ошибка в выражении `when:` | прерывание с позицией внутри выражения |
| Несуществующий `${bundle.input.<id>}` в активной ветке | прерывание |
| Несуществующий `${bundle.input.<id>}` внутри `false`-ветки | игнорируется (не вычисляется) |
| Тот же `${bundle.input.<id>}` внутри code fence | остаётся текстом, ошибкой не считается |

## Полный пример

```md
---
description: Code review для проекта ${bundle.input.projectName}
model: ${bundle.input.model}
---

# /review

Запусти ревью текущей ветки.

<!-- when: ${bundle.input.profile} == 'full' -->
Полный профиль:
- статический анализ
- прогон тестов
- security-review
<!-- end -->

<!-- when: 'security-review' in ${bundle.input.skills} -->
После основного ревью активируй скилл `security-review`.
<!-- end -->

Затронутые модули: ${bundle.input.modules}.

<!-- when: ${bundle.input.strict} -->
В strict-режиме:
- не делай force push;
- не используй `rm -rf` без явного подтверждения.
<!-- end -->
```

При `profile = 'minimal'`, `skills = ['review']`, `strict = false`, `projectName = 'ai-kit'`, `model = 'sonnet'`, `modules = ['core','cli']` итог:

```md
---
description: Code review для проекта ai-kit
model: sonnet
---

# /review

Запусти ревью текущей ветки.

Затронутые модули: core, cli.
```
